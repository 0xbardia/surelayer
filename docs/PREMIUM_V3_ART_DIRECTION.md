# SureLayer Premium Experience V3

## Visual critique

The current V2 production experience is credible, readable, and consistently
branded. The warm paper/ink/brass palette, Georgia display type, truthful
protocol language, custom mark, and reduced-motion handling are strengths to
preserve. The hero already explains the core idea above the fold, and the app
surfaces are more considered than a default dashboard.

The remaining gap is authorship. Most pages still use the same visual grammar:
large page heading, a surface/card group, and a repeated brass rule. The landing
sections read as a stack of good blocks instead of one composed argument. The
hero diagram is attractive but still reads as a panel containing components;
its lifecycle relationship is not yet the dominant visual. Claims are an index
with premium styling, but not yet a distinctive ledger. Claim detail has the
right data and hierarchy, but can feel like a long article beside a sidebar.
Create and Account are polished forms/panels rather than unmistakable product
moments. Motion is present, but most of it is entry/hover feedback instead of
meaningful protocol choreography.

## What stays

- The existing routes, data contracts, wallet boundaries, pending-write
  protection, and finality semantics.
- Warm mineral surfaces, near-black ink, restrained brass, semantic moss/rust,
  editorial serif display type, and monospace protocol metadata.
- Honest copy: conceptual diagrams remain labeled, and no live metrics or
  validator telemetry are invented.
- CSS/SVG motion and native browser behavior; no heavy visual dependency.

## One visual world

**Assurance instrument**: an institutional evidence terminal designed like a
carefully printed protocol record. The interface moves from paper-like canvas
to ink protocol plane to a decisive ledger imprint. It should feel tactile and
precise, like a high-value document being registered—not like a SaaS dashboard
or a futuristic crypto interface.

Primary motif: **the assurance imprint** — a layered registration mark where
independent evidence paths converge and leave a clear final trace.

Supporting motif: **the ledger rule** — a measured horizontal/vertical line
system that organizes issuer, challenger, evidence, consensus, and settlement.
It gives different screen types a shared rhythm without repeating the same card
layout.

## V3 composition

- Landing becomes a single narrative: unpriced claims → bonded commitment →
  challenge → independent evaluation → verdict → settlement.
- The hero becomes a protocol instrument with a central imprint, branching
  traces, and a clear claim/bond/evidence/verdict sequence.
- One full-width narrative section uses pinned editorial copy and progressive
  rule drawing; content remains visible without animation.
- Claims use a ledger/index layout with stronger numbering, state bands, and
  deliberate density.
- Claim detail becomes a digital assurance certificate with a strong record
  header, inline economic exposure, evidence register, verdict imprint, and
  timeline.
- Create is an issuance workstation with a live, data-backed warranty preview.
- Challenge is a sober adversarial record showing issuer position versus
  challenger commitment.
- Account is a compact protocol ledger rather than a dashboard of tiles.

## Motion language

Motion should feel registered, not flashy: short optical corrections for
controls, measured line-drawing for protocol relationships, and one-time
imprints when a state is revealed. Use a shared duration/easing scale and
transform, opacity, clip-path, or SVG stroke offset. Never imply that a
conceptual animation is live validator telemetry or that visual progress is
protocol progress.

## Constraints and risk controls

- No changes to `contracts/SureLayer.py`, contract address, economics, runtime
  configuration, SDK write routing, or finality handling.
- No new dependency unless the existing CSS/SVG/native approach cannot meet a
  measured requirement; default is zero new dependencies.
- No fake validators, claims, volume, balances, partners, or success rates.
- Preserve semantic headings, labels, focus states, touch targets, wrapping
  addresses, and an immediate reduced-motion fallback.
- Keep animated regions layout-stable and cap hero/scroll choreography so task
  completion never waits on motion.
